# 법제처 Open API 인증키 발급 가이드

> 본인 한도로 korean-law MCP를 이용하려면 법제처 Open API 인증키, 즉 `OC` 값을 설정합니다.
> 2026-11-08 확인한 upstream 플러그인은 공개 서버에 연결하며 OC 없이도 공용 한도로 조회합니다. 로컬 서버 방식은 OC가 필요합니다. 설치 시 최신 [공식 프로젝트 안내](https://github.com/chrisryugj/korean-law-mcp)와 실제 플러그인 설정을 확인하세요. 공용 조회 성공을 본인 키 설정 완료로 보고하지 않습니다.

## Claude가 브라우저로 초기설정을 도울 때

전체 설치 또는 korean-law 초기설정 요청을 받으면 이 절차를 실행합니다. URL을 열어 주는 데서 끝내지 말고, 사용 가능한 브라우저 도구로 화면을 읽고 클릭·입력하며 설정 완료까지 돕습니다. 이미 유효한 본인 OC로 조회된다면 새 신청이나 키 재발급을 하지 않습니다.

### 1. 브라우저 연결 확인

- 현재 Claude 세션에 실제로 노출된 브라우저·화면 조작 도구부터 확인합니다. 도구 이름을 추측하거나 WebFetch로 로그인 화면을 읽은 것만으로 브라우저 연결이 됐다고 하지 않습니다.
- CLI에서 브라우저가 연결되지 않았다면 [Claude Code의 Chrome 연동 안내](https://code.claude.com/docs/en/chrome)에 따라 Claude in Chrome 확장과 `/chrome` 연결 상태를 확인하도록 안내합니다. 필요한 경우 사용자가 `claude --chrome`으로 로컬 세션을 시작하고 기존 설치 단계에서 이어갑니다. 확장 설치·사이트 접근 권한은 호스트의 정상 승인 절차를 따릅니다.
- 데스크톱 앱은 그 세션에서 제공되는 브라우저/컴퓨터 조작 기능을 먼저 사용합니다. 데스크톱에 CLI의 `/chrome`이 있다고 가정하지 않습니다. 기능이 없으면 Chrome 연동을 지원하는 로컬 CLI 등으로 이어갈 방법을 안내합니다. Windows에서 이 경로는 네이티브 Claude Code를 사용하며 WSL의 Chrome 연동을 전제하지 않습니다.
- 연결 후 실제 탭 목록이나 공개 페이지를 읽어 제어 가능함을 확인합니다. 세션·계정·조직 정책상 도구를 사용할 수 없다면 `브라우저 연결 대기`와 필요한 조치를 기록하고 다른 구성요소 설치는 계속합니다. 사용자 브라우저의 쿠키·로그인 DB를 추출해 우회하지 않습니다.

### 2. 계정이 없으면 회원가입부터 진행

계정이 없는 상태도 정상적인 초기설정 시작점입니다. “먼저 가입하고 오세요”로 작업을 종료하지 않습니다. 계정 유무를 확인하고, 기존 계정이면 로그인·계정 찾기를 돕고 신규 가입은 건너뜁니다. 비로그인 상태라는 이유만으로 새 계정을 만들지 않습니다.

1. 공식 사이트의 **로그인 → 사용자 가입**으로 이동합니다. [공개 가입 화면](https://open.law.go.kr/LSO/usrJoin.do)에서 실제 항목과 진행 순서를 읽습니다. 2026-11-08 확인한 화면은 이메일 계정, 개인/기업 구분, 본인인증과 함께 `openAPI를 신청합니다` 항목을 제공합니다. 화면이 바뀌면 현재 표시를 따릅니다.
2. 사용자가 회원가입을 요청·허용한 범위에서 이름·가입 이메일·개인/기업 구분·연락처·기관 정보 등 일반 항목의 작성을 돕습니다. 이미 제공된 정보는 재사용하고, 모르는 필수 항목만 모아서 질문합니다. 가짜 개인정보나 임의 기업명을 만들지 않습니다. 본인인증으로 채워지는 항목은 확인 전 강제로 덮어쓰지 않습니다.
3. 약관·개인정보 동의, 휴대전화·아이핀 등의 본인인증, 인증번호·CAPTCHA는 사용자가 브라우저에서 직접 처리합니다. 비밀번호는 공식 사이트의 입력란 또는 검증된 보호 입력창에서 받습니다. 비밀번호 자동 입력 자체를 금지하지는 않지만, 팝업의 값을 모델·도구 호출 인자·로그로 반환하지 않고 로컬 도구가 확인된 대상 사이트의 비밀번호 칸에 직접 전달할 수 있어야 합니다. 그 경로가 없으면 공식 사이트의 입력란에 사용자가 입력한 뒤 Claude가 다음 단계부터 이어갑니다. 인증창이 별도 창으로 열리면 위치를 안내하고, 비밀번호·인증번호·주민번호를 채팅으로 받거나 인증 화면을 기록하지 않습니다.
4. 사용자 조치가 끝나면 현재 화면을 다시 읽고 다음 일반 입력부터 이어갑니다. 인증창 닫힘이나 사용자 완료 메시지만으로 본인인증 성공을 단정하지 않고, 가입 페이지의 완료 표시·오류를 확인합니다. 인증 실패·팝업 차단·만료가 있으면 해당 단계만 복구합니다.
5. 가입과 API 신청을 함께 할 수 있으면 korean-law 초기설정 범위에서 해당 경로를 사용합니다. 아래 API 신청 절차에 따라 시스템·사용 목적 등을 작성합니다. 화면에서 OC를 직접 지정하게 하면 허용 형식과 중복 검사를 확인하고 사용자에게 보호된 입력란에서 지정하도록 안내합니다. 이메일 앞부분이나 예시 문자열을 실제 키로 추정하지 않습니다.
6. 가입·API 신청 내용을 검토할 수 있게 정리한 뒤, 사용자가 승인한 제출 범위에서 가입을 완료합니다. 회원가입과 API 신청의 동의를 구분하고 사용자가 직접 처리한 약관 선택을 바꾸지 않습니다. 이미 승인된 제출을 반복 확인하지 않습니다. 중복 이메일이면 계정 찾기·로그인으로 전환하며, 제출 결과가 불명확하면 상태 확인 전 재전송하지 않습니다.
7. 가입 성공 표시와 실제 로그인 상태를 확인합니다. 추가 이메일 확인 등이 요구되면 해당 사용자 조치 후 재개합니다. 가입 중 API도 신청했다면 마이페이지의 신청·OC 상태를 확인하고 **별도 API 신청을 중복 실행하지 않습니다**. 가입만 완료됐다면 다음 API 신청 단계로 넘어갑니다.

### 3. 공식 사이트에서 API 신청 상태 확인

1. [국가법령정보 공동활용](https://open.law.go.kr/LSO/openApi/guideList.do)을 새 작업 탭에서 엽니다. 메뉴·버튼·필수 필드는 **현재 화면**을 기준으로 찾습니다. 저장한 좌표나 숨은 API 호출에 의존하지 않습니다.
2. 로그인이 필요하면 사용자에게 브라우저에서 직접 로그인하도록 안내하고, 완료 후 화면을 다시 읽고 이어갑니다. 계정이 없으면 앞 절의 회원가입부터 진행합니다. 가입과 함께 API를 신청했다면 그 처리 결과부터 확인합니다.
3. 기존 신청·승인·OC 발급 여부부터 확인합니다. 이미 발급된 키가 있으면 재발급 버튼을 누르지 않습니다. 신청 중이면 새 신청서를 중복 제출하지 않습니다.
4. 신청이 필요하면 현재 화면의 **OPEN API 신청** 메뉴로 이동합니다. 아래 예시를 참고해 실제 이용 목적과 필요한 법령·판례 조회 항목을 채웁니다. 이름·기관·연락처·사이트 주소는 사용자에게 받은 사실만 사용합니다. 모르는 필수 값은 필요한 항목을 묶어 물어봅니다. 주소 형식이 필요한 칸에 임의 도메인이나 `개인 PC 로컬 사용`이라는 문장을 넣지 않습니다.
5. 제출할 내용을 사용자에게 간단히 보여 줍니다. 사용자가 해당 내용의 신청 제출을 승인한 범위에서 저장·신청을 진행하고, 이미 승인한 내용을 다시 묻지 않습니다. 일반적인 프로그램 설치 요청만으로 계정 생성·약관 동의·임의 개인정보 제출까지 승인됐다고 해석하지 않습니다.
6. 제출 후 성공·보완 요청·승인 대기 메시지를 확인합니다. 승인 대기이면 완료로 표시하지 말고 현재 상태와 재개 메뉴를 남깁니다. 승인·발급이 가능한 상태이면 **API인증키관리**로 이동합니다. 메뉴 구조가 달라졌으면 공식 화면의 안내를 따릅니다.

### 4. OC를 플러그인에 연결

- 브라우저의 OC 화면과 설치된 korean-law 플러그인의 설정 위치까지 안내합니다. macOS·Windows에서는 아래 **로컬 OC 입력창**을 먼저 사용합니다. 사용자가 창에 키를 넣으면 로컬 도구가 Claude 설정에 직접 전달하고 에이전트에는 성공·실패만 반환합니다. 키를 사용자에게 채팅으로 보내 달라고 하지 않습니다. 입력창을 사용할 수 없으면 플러그인의 민감값 입력란이나 호스트의 보호된 입력 경로를 사용합니다. 키가 보이는 화면·HTML·설정 전체를 로그·보고서로 남기지 않습니다.
- 현재 upstream의 플러그인 설정 항목은 `api_key`이며, 공개 서버 `https://mcp.gomdori.app/law`에 키를 헤더로 전달합니다. 실제 설치 버전의 manifest와 설정 UI를 확인해 적용합니다. 기존 로컬 서버를 쓰는 사용자를 공개 서버로 임의 전환하지 않습니다. 공개 서버를 경유하지 않으려는 경우 upstream의 로컬 서버 설정 안내를 따릅니다.
- 새 설치는 아래 플러그인 등록 절차를 사용합니다. 이미 설치했다면 `/plugin`의 설치된 플러그인 설정 화면에서 키를 등록·수정합니다. CLI 사용 시 먼저 `claude plugin configure --help` 등 실제 도움말을 확인합니다. 키를 명령행 인자나 URL에 직접 삽입하지 않고 민감값 입력을 지원하는 경로를 사용합니다. 저장소의 `.mcp.json`이나 배포 파일에 키를 넣지 않습니다.
- 키를 입력한 뒤 화면을 다시 확인하고, 호스트 안내에 따라 플러그인을 다시 로드하거나 새 세션에서 연결을 확인합니다. 다른 MCP 설정은 보존합니다. 안전한 입력 경로가 없으면 키 등록만 사용자 조치 대기로 남깁니다.

#### 로컬 OC 입력창

플러그인 설치 후 저장소 루트에서 [입력창 도구](../scripts/configure_korean_law.py)를 실행합니다. Python 3와 macOS/Windows의 기본 대화상자를 사용하며 별도 웹서버나 UI 패키지를 설치하지 않습니다.

```bash
python3 scripts/configure_korean_law.py
```

Windows에서 번들 CLI를 사용하는 경우 발견한 실제 경로를 지정합니다.

```powershell
python scripts/configure_korean_law.py --claude 'C:\확인한 경로\claude.exe'
```

입력은 화면에서 가려지며 로컬 자식 프로세스의 출력은 도구 내부에서만 받습니다. 값은 `claude plugin configure korean-law@korean-law-marketplace --values-stdin`의 JSON 표준입력으로 전달됩니다. 도구는 키를 파일·명령행 인자에 넣거나 출력하지 않고, 저장은 Claude의 플러그인 설정 기능이 담당합니다. 취소·빈 입력은 설정을 바꾸지 않습니다. CLI가 값을 오류에 포함하더라도 도구는 그 출력을 에이전트에 전달하지 않습니다. 저장 성공은 실제 조회 성공과 별도로 확인합니다.

이 도구는 **OC 설정 전용**이며 법제처 로그인 비밀번호를 입력하는 곳이 아닙니다. 비밀번호용 팝업을 별도로 붙일 때도 입력값을 채팅 밖에서 받는 것만으로는 충분하지 않습니다. 대상 사이트 확인과 로컬 직접 전달이 모두 지원되어야 하며, 지원되지 않는 브라우저 도구에 비밀번호를 인자로 넣지 않습니다.

### 5. 실제 조회까지 확인하고 종료

1. `korean-law`가 연결되어 있고 도구가 노출되는지 확인합니다. 등록 목록에 이름이 있다는 사실만으로 끝내지 않습니다.
2. 현재 노출된 도구의 실제 스키마를 읽고, 공개적인 테스트 질의인 `민법 제750조`를 검색한 다음 반환된 식별자로 본문을 조회합니다. 본문·법령명·조문·출처가 반환되는지 확인합니다. 실제 사건자료를 테스트에 사용하지 않습니다.
3. 조회 결과와 함께 본인 키가 민감 설정에 저장·적용됐는지 값 노출 없이 확인합니다. 공용 서버는 키가 없어도 응답할 수 있으므로, 조회 성공만으로 본인 OC가 적용됐다고 추정하지 않습니다. 적용 여부를 확인할 수 없으면 `조회 성공 / 본인 OC 적용 미확인`으로 구분합니다.
4. `브라우저 연결`, `가입·로그인`, `API 신청·승인`, `OC 설정`, `MCP 연결`, `실제 본문 조회` 각각의 상태와 남은 사용자 조치를 보고합니다. 오류가 있으면 해당 단계로 돌아가 복구하고, 승인 대기·사용자 입력 대기 동안 다른 설치는 계속합니다. 내장 오프라인 스냅샷 응답을 온라인 조회 성공으로 대체하지 않습니다.

브라우저가 없는 경우의 대체 경로는 아래 수동 안내입니다. 브라우저 도구가 있는데도 클릭·입력을 모두 사용자에게 떠넘기지 않습니다.

### 6. 실제 검증 시나리오

| 시작 상태 | 확인할 결과 |
|---|---|
| 법제처 계정 없음 | 가입 화면 진입·입력 지원 → 사용자 동의·본인인증·비밀번호 입력 → 가입 성공·로그인 → API 신청·OC 설정 → 실제 본문 조회까지 진행 |
| 신규 가입 중 API 동시 신청 | 가입 후 신청·OC 상태를 확인하고 중복 신청 없이 MCP 설정으로 진행 |
| 계정만 있고 API 신청 없음 | 기존 계정으로 로그인 후 API 신청부터 진행. 신규 계정 생성 없음 |
| 기존 OC 있음 | 가입·신청·재발급 없이 기존 키 설정과 실제 조회 확인 |
| OC 입력창 사용·취소·등록 오류 | 입력값은 채팅·명령행·출력에 나타나지 않음. 등록은 표준입력 사용, 취소는 기존 설정 보존, 오류 메시지는 값 없이 보고 |
| 인증 실패·이메일 중복·팝업 차단 | 실패 지점에서 복구·사용자 조치 후 이어가기. 중복 계정·신청 없음 |
| 브라우저 도구 없음·신청 처리 대기 | 구체적 대기 사유와 재개 지점을 보고하며 다른 설치 계속. 완료로 오보고하지 않음 |
| 완료 후 새 Claude 세션·재실행 | 설정이 유지되고 실제 조회 가능. 계정·키·MCP 중복 생성 없음 |

신규 가입 검증은 실제 가입을 원하는 사용자와 함께 수행합니다. 테스트를 위해 가짜 계정을 만들거나 기존 계정을 지우지 않습니다. 보고서에는 시나리오별 시작 상태·통과/실패·남은 작업을 남기되 개인정보·인증값을 제외합니다. 기존 계정 경로만 시험했다면 신규 가입 경로는 미검증으로 표시합니다.

## 1분 요약

1. [국가법령정보 공동활용](https://open.law.go.kr/LSO/openApi/guideList.do)에 접속합니다.
2. 오른쪽 위 **로그인**을 누릅니다. 계정이 없으면 **사용자 가입**을 먼저 합니다.
3. 왼쪽 메뉴에서 **OPEN API 신청**을 누릅니다.
4. 실제 이용 목적·개인/기관 정보에 맞게 신청서를 작성·저장합니다. 신청 목적 예시는 아래 표를 참고하고, 현재 화면의 필수 형식과 승인 절차를 따릅니다.
5. 왼쪽 메뉴에서 **API인증키관리**를 열고 **현재 API인증키(OC)** 값을 복사합니다.
6. `install.sh` 또는 `korean-law` 설치 프롬프트에 그 값을 붙여넣습니다. 이미 설치를 마쳤다면 아래 수동 설치 명령으로 나중에 추가합니다.

공식 사이트에서 키 이름은 보통 `API인증키`, `OC`, `현재 API인증키(OC)`로 표시됩니다.

## 신청서에 무엇을 쓰나

개인 변호사·사무소 내부 사용이면 아래처럼 적으면 충분합니다.

| 항목 | 예시 |
|---|---|
| 사용 목적 | Claude Code에서 법령·판례 원문 확인 및 인용 검증 |
| 활용 서비스 | 법령 본문 조회, 판례 목록/본문 조회 |
| 이용 형태 | 개인 PC 또는 사무소 내부 업무용 |
| 사이트/도메인 | 실제 사무소 홈페이지 주소가 있으면 사용. 없으면 화면의 로컬 사용 선택·안내를 따르고 가짜 주소를 만들지 않음 |
| 비고 | `korean-law-mcp`로 법제처 Open API를 호출 |

사이트 화면 구성이 바뀔 수 있습니다. 기존 신청 상태부터 확인하고, 신청·승인이 필요한 경우 완료한 뒤 API인증키관리에서 OC를 확인합니다.

## 기존 셸 설치기를 직접 사용하는 경우

이 절은 대화형 `install.sh`의 기존 동작입니다. Claude가 맡는 전체 설치에서는 OC가 없다는 이유로 여기서 종료하지 말고 위 브라우저 초기설정 절차로 이어갑니다.

전체 설치 중 이런 문구가 나오면, 이미 복사한 `OC` 값이 있을 때만 `y`를 입력해 korean-law MCP 설치를 진행합니다.

```text
법제처 Open API 키(OC)를 지금 갖고 있나요? [y/N, 엔터=아니오]
```

OC가 아직 없으면 Enter로 건너뛰어도 됩니다. 설치는 계속되고, `/jurisupport:offline-law-fallback`으로 헌법, 민법, 민사소송법, 형법, 형사소송법, 상법, 주요 특별형법 전문 스냅샷을 이용해 실습할 수 있습니다.

OC 발급 후 Claude Code 안에서 다음을 실행합니다.

```text
/plugin marketplace add chrisryugj/korean-law-mcp
/plugin install korean-law@korean-law-marketplace
```

설치가 끝난 뒤 Claude Code에서 확인:

```text
/mcp
```

`korean-law`가 보이면 다음처럼 테스트합니다.

```text
korean-law MCP로 민법 제750조 본문을 확인해줘.
```

## 급할 때 임시 진행

강의나 데모처럼 당장 발급이 막힌 경우에는 korean-law MCP 설치를 건너뛰고, JuriSupport 플러그인에 포함된 오프라인 법령 스냅샷을 사용합니다.

```text
/jurisupport:offline-law-fallback
```

오프라인 스냅샷 포함 범위:

- 대한민국헌법
- 민법, 민사소송법
- 형법, 형사소송법
- 상법
- 주요 특별형법 전문

다만 이는 기준일 2026-06-14의 실습용 스냅샷입니다. 실제 사건 검증 전에는 반드시 본인 `OC`로 korean-law MCP를 설치하고 최신 조문·판례를 재검증하세요.

| 조회는 되지만 OC 입력 여부가 불명확 | 공용 한도 응답일 수 있습니다. 본인 키 설정 상태와 실제 조회 상태를 별도로 확인합니다. |
