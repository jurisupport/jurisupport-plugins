# 허위 사건번호 확인 (case-number-verify)

먼저 [공통 실행 규칙](../../references/runtime.md)을 읽고 현재 호스트에서 사용 가능한 기능으로 수행한다.

> **⚠️ 경고: 이 도구는 1차로 걸러내는 용도로만 쓴다.**
> 판례 환각은 없는 사건번호를 지어내는 것만이 아니다. 다음도 모두 환각이다.
> - **사건번호는 있으나 인용이 다르다**: 법원·선고일·사건부호·판결/결정 구분·전원합의체 여부가 틀린다.
> - **사건은 있으나 취지를 잘못 옮긴다**: 판결의 결론·쟁점을 거꾸로 또는 다른 쟁점으로 소개한다.
> - **판결에 없는 문장을 지어낸다**: 판시 문구를 그럴듯하게 만들어 큰따옴표로 인용한다.
>
> 「사건번호가 존재합니다」는 위 세 가지를 하나도 걸러 주지 못한다. 존재 확인을 통과한 판결도 **판결 전문을 직접 열어** 법원·선고일·판시 문언·취지를 대조한 뒤에만 서면에 쓴다(lbox 등 판결 전문·진본 PDF, `lbox-guide` 참고).
> 보고할 때도 「사건번호 존재 확인」과 「판시 내용 확인」을 나눠 적는다. 앞의 것만 했으면 판시 내용은 `[미확인]`으로 표시한다.

사법정보공개포털 「허위 사건번호 확인」 화면에서 사건번호가 존재하는지만 확인한다.
- URL: https://portal.scourt.go.kr/pgp/index.on?m=PGP210M01&l=N&c=200
- 이 서비스는 **사건번호의 존재 여부만** 알려 준다. 판결 내용·선고일·판시가 맞는지는 알려 주지 않는다.
- 포털 안내문 그대로: 「본 사이트에서 제공된 정보는 법적인 효력이 없으며」, 「사건 진행 상태 및 유형에 따라 확인되지 않거나 판결서가 부존재할 수 있습니다.」

## 원칙 (반드시 지킨다)

1. **자동입력방지 숫자는 사람이 넣는다.** Claude는 캡차 이미지를 읽어 숫자를 넣지 않는다. OCR·음성듣기 판독·외부 풀이 서비스도 쓰지 않는다.
2. 캡차 이미지를 사용자에게 보여 주고 숫자 6자리를 받는다. 받은 숫자만 `answer`에 넘긴다.
3. 메신저(텔레그램 등)로 대화 중이면 선택형 질문 도구를 쓰지 않고 답장으로 숫자를 받는다.
4. 「존재함」은 「사건번호가 있다」는 뜻일 뿐이다. 판시 내용까지 확인됐다고 보고하지 않는다. 판시·선고일 확인은 판결 전문(lbox 등)으로 한다.
5. 「없음」이 나와도 바로 「허위」라고 단정하지 않는다. 법원·부호·연도 입력을 다시 보고, 법원을 추정(`courtGuessed: true`)했으면 그 사실을 함께 보고한다.

## 사용법

이 `SKILL.md`와 같은 폴더의 `cnv.js`를 쓴다. 요구사항: Node.js 18 이상, Google Chrome.
처음 한 번은 같은 폴더에서 의존성(playwright-core)을 설치한다. `node_modules`가 이미 있으면 건너뛴다. 브라우저는 내려받지 않고 시스템 Chrome을 쓴다.

```bash
cd "<이 SKILL.md가 있는 실제 폴더>"
[ -d node_modules/playwright-core ] || npm install --omit=dev --no-audit --no-fund
node cnv.js parse "대법원 2018. 10. 30. 선고 2013다61381 전원합의체 판결"   # 해석만 확인
node cnv.js start                     # 백그라운드 세션 시작(20분 미사용 시 자동 종료)
node cnv.js check "<사건번호들이 든 문장>"   # 첫 사건 입력 + 캡차 PNG 저장 → 경로 출력
node cnv.js answer 123456             # 사용자가 읽어 준 숫자로 검색 → 결과 + 다음 사건 캡차
node cnv.js refresh                   # 캡차가 안 보이면 새로 받기
node cnv.js status                    # 대기열·결과 보기
node cnv.js stop
```

브라우저 창에서 사용자가 직접 입력하는 방식:
```bash
node cnv.js start --headed
node cnv.js check "..."
# 사용자가 창에서 숫자 입력 후 「검색」 클릭
node cnv.js answer --browser          # 결과를 읽어 온다(최대 3분 대기)
```

결과 폴더 지정: `start --out <폴더>`. 기본값은 `~/.cache/case-number-verify/`.
사건 작업 중이면 `--out "<사건 작업폴더>/허위사건번호확인"`처럼 작업폴더를 준다.

## 진행 순서

1. `parse`로 해석 결과를 먼저 본다. `error`가 있는 항목(법원 미상, 헌법재판소 사건)은 사용자에게 알린다.
2. `start` → `check`.
3. 출력된 `captcha` 경로를 `![자동입력방지 문자](<경로>)`로 보여 주고 숫자 6자리를 요청한다.
4. 받은 숫자로 `answer`. 결과가 `retry: true`면 새 `captcha`를 다시 보여 준다.
5. `next.captcha`가 있으면 3으로 돌아간다. `next.done`이면 `stop`.
6. 결과를 표로 보고한다: 입력 문구 / 조회한 사건번호 / 판정 / 포털 문구 / 법원 추정 여부 / 캡처 경로.
7. 보고 끝에 위 경고를 붙인다. `EXISTS` 판결마다 「판시 내용 [미확인] — 전문 대조 필요」를 적는다.

## 판정 값

| verdict | 포털 문구(2026-11-19 확인) | 보고 |
|---|---|---|
| `EXISTS` | 「사건번호가 존재합니다.」 | 사건번호가 있다. 판시 내용은 별도 확인 |
| `NOT_FOUND` | 「사건번호가 존재하지 않습니다. 허위 정보일 수 있으니 주의바랍니다.」 | 사건번호가 없다. 입력값 재확인 후 허위 의심 |
| `CAPTCHA_WRONG` | 자동입력방지 오류 문구 | 새 캡차로 다시 받는다(기록하지 않음) |
| `UNKNOWN` | 그 밖의 문구 | `message`·캡처를 그대로 보여 주고 판단을 묻는다 |

`CAPTCHA_WRONG` 문구는 실제로 아직 보지 못했다. 처음 나오면 `message`를 보고 `classify()` 정규식을 고친다.

## 사건번호 해석 규칙

- 패턴: `연도(4자리) + 부호(한글 1~5자) + 번호(1~7자리) [-가지번호]`. 예: `2013다61381`, `2021고단123`, `2020가합12345-1`
- 법원: 사건번호 앞 문장에서 포털 법원 목록(`courts.json`, 211개)과 맞는 가장 긴 이름을 찾는다. 「서울고법·수원지법 안산지원」 같은 약칭은 정식 명칭으로 바꿔 찾는다.
- 법원 표시가 없고 부호가 대법원 부호(다·도·두·므·스·마·그·모·추·수·우·누·재○ 등)면 대법원으로 추정하고 `courtGuessed: true`를 붙인다.
- `헌가·헌마·헌바` 등 헌법재판소 사건은 이 서비스 대상이 아니다.
- 법원 목록이 바뀌면 `courts.json`을 다시 만든다(포털 `#mf_mainFrame_sbx_cortCd` 옵션).
